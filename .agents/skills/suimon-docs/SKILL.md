# suimon の文書作成

このリポジトリ専用の文書作成・整理ルール。文書を残すことを前提にせず、情報そのものが必要かを判断する。

## 内容の判断

- 書く前に、対象の実装・型・スキーマ・コメント・テストを確認する。コードを参照すれば自明なことは文書に書かない。
- API の詳細、引数・既定値、処理の流れ、コンポーネント一覧、定理の主張、検証項目などを日本語で再記述しない。「詳細だから」「公開契約だから」「保証だから」は別文書を維持する理由にならない。
- 残すのは、なぜその設計を選んだか、避けた代案とその問題、判断に影響した制約・トレードオフ。設計理由という見出しでも、本文が動作説明だけなら削る。文書を残すために理由を後付けしない。
- README は目的・最小の実行手順・参照先に絞る。使い方は既存の動くサンプルへ案内し、コードを転記しない。トップ README に言語別の説明を増やさず、実装ディレクトリへ案内する。
- 内部の開発番号、過去の完了報告、不要な AI 利用の経緯、別用途から借りた具体例は載せない。
- suimon は現時点で未公開。開発途中の版に対する互換性・移行案内や、仮想の旧版利用者向けの説明は不要。公開後に実際の対象が生じた場合にだけ必要性を見直す。

## 文書の配置

- 新しい文書には、既存文書やコードへの参照では足りない理由が必要。リンクを中継するだけの一覧や、実装を解説し直す文書は作らない。
- ファイル数を減らすために単純結合しない。重複と不要な情報を削り、必要な部分だけを読める構成にする。
- 削除対象を別の文書やコメントへ丸ごと移さない。コード側に補足する場合も、実装から自明でない契約・理由だけを該当箇所へ短く書く。

## 精査と確認

- 精査では各文書の本文とコードを照合する。見出しやキーワード検索だけで必要と判断しない。
- 精査・一覧だけを求められた場合は編集せず、ファイルごとに残す・縮小する・削除するの判断と、残す内容・削る内容・根拠を一覧にする。
- 作成・修正後は、リンク先・アンカー・削除済み文書への参照を確認する。コードで分かる説明や、根拠のない設計理由が増えていないか読み直す。
